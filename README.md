# Gretza Roman Homes and Loans

Marketing website for **Gretza Roman Homes and Loans** — a real estate agency
that also helps clients with home loans and mortgages. Built with Next.js 14
(App Router), TypeScript, and Tailwind CSS.

> This branch replaces the previous AI-portfolio site at `/`. The portfolio
> remains on the repository's default branch. The portfolio's chat API
> (`app/api/chat`) and components are left in place but unused by the new site.

## Getting started

```bash
npm install
npm run dev       # http://localhost:3000
npm run build     # production build (Vercel-ready)
```

No environment variables are required for the real estate site.

## Pages

| Route | Purpose |
|---|---|
| `/` | Home — hero carousel, price-band cards, loan teaser, featured listings, testimonials |
| `/listings` | Listing grid, filterable by price range and property type (URL-driven, shareable) |
| `/loans` | Loan programs + interactive mortgage payment calculator |
| `/about` | Agent bio, credentials, service area |
| `/contact` | Validated contact form (posts to `/api/contact`), phone/email, embedded map |

`sitemap.xml` and `robots.txt` are generated by `app/sitemap.ts` / `app/robots.ts`.

## Editing content

All content lives in small, plain data files — no code changes needed:

- **Brand / contact info** — `lib/site.ts` (name, phone, email, service area).
  The phone number and office address are placeholders; TODOs mark them.
- **Listings** — `lib/listings.json`. Each entry has price, beds/baths, sqft,
  address, `band` (price range) and `type` (used by the filters), and an image
  path.
- **Hero slides** — `lib/hero-slides.ts`
- **Testimonials** — inline in `app/page.tsx`

### Plugging in real MLS / IDX data later

`lib/listings.ts` is the single access point for listing data. To go live with
real inventory, replace the `listings.json` import there with a fetch from your
MLS/IDX provider (e.g. an IDX API, RESO Web API, or a CMS collection) that maps
into the same `Listing` shape — every component reads through that module, so
nothing else changes.

## Images

The Higgsfield MCP connector (Seedance 2.0) was not connected when the site was
scaffolded, so all photography is currently **labeled SVG placeholders** in
`public/images/`. The exact generation prompt for every asset is documented in
[`public/images/HIGGSFIELD_PROMPTS.md`](public/images/HIGGSFIELD_PROMPTS.md),
and each usage site carries a `TODO(Higgsfield)` comment. After generating the
real `.jpg` assets, update the paths in `lib/hero-slides.ts` and
`lib/listings.json`, and remove `images.dangerouslyAllowSVG` from
`next.config.mjs`.

## Contact form

`app/api/contact/route.ts` validates submissions and logs them — it's a
placeholder. Before launch, wire it to email (Resend/SendGrid), a CRM webhook,
or a database; the TODO in that file marks the spot.

## Deploying

The project is Vercel-ready (`vercel.json` included): import the repo, keep the
default Next.js settings, and deploy.
